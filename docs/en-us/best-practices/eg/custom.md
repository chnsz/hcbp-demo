# Deploy Custom Event Subscription

## Application Scenario

EventGrid (EG) is an event-driven architecture service provided by Huawei Cloud, supporting event production, routing, transformation, and consumption. With custom event channels and custom event sources, you can ingest custom events generated by your business systems into EventGrid and route them to a specified HTTPS event target as needed.

This best practice will introduce how to use Terraform to automatically deploy a custom event channel, a custom event source, and an event subscription, implementing the complete pipeline from custom event ingestion and filtering to distribution to an HTTPS target, helping you quickly build loosely coupled and scalable event-driven applications.

## Operation Steps

### 1. Script Preparation

Prepare the TF file (such as main.tf) for writing the current best practice script in the specified workspace, ensuring that it (or other TF files in the same directory) contains the provider version declaration and Huawei Cloud authentication information required for deploying resources.
For configuration introduction, refer to the introduction in [Preparation Before Deploying Huawei Cloud Resources](../../introductions/prepare_before_deploy.md).

### 2. Create a Custom Event Channel

Add the following script in the TF file (such as main.tf):

```hcl
# Create a custom event channel in the specified region (if the region parameter is omitted, it inherits the region specified in the current provider block)
variable "channel_name" {
  description = "The name of the custom event channel"
  type        = string
}

resource "huaweicloud_eg_custom_event_channel" "test" {
  name = var.channel_name
}
```

**Parameter Description**:
- **name**: The name of the custom event channel, assigned by referencing the input variable channel_name

### 3. Create a Custom Event Source

Add the following script in the TF file (such as main.tf):

```hcl
# Create a custom event source in the specified region (if the region parameter is omitted, it inherits the region specified in the current provider block)
variable "source_name" {
  description = "The name of the custom event source"
  type        = string
}

variable "source_type" {
  description = "The type of the custom event source"
  type        = string
  default     = "APPLICATION"
}

resource "huaweicloud_eg_custom_event_source" "test" {
  channel_id = huaweicloud_eg_custom_event_channel.test.id
  name       = var.source_name
  type       = var.source_type
}
```

**Parameter Description**:
- **channel_id**: The ID of the event channel to which the custom event source belongs, assigned by referencing the ID of the custom event channel created in the previous step
- **name**: The name of the custom event source, assigned by referencing the input variable source_name
- **type**: The type of the custom event source, assigned by referencing the input variable source_type, defaulting to APPLICATION

### 4. Query EG Connections

Add the following script in the TF file (such as main.tf):

```hcl
# Query EG connections in the specified region (if the region parameter is omitted, it inherits the region specified in the current provider block)
variable "connection_name" {
  description = "The exact name of the connection to be queried"
  type        = string
  default     = "default"
}

data "huaweicloud_eg_connections" "test" {
  name = var.connection_name
}
```

**Parameter Description**:
- **name**: The name of the EG connection to be queried, assigned by referencing the input variable connection_name, defaulting to default

### 5. Wait for the Custom Event Channel and Source to Be Ready

Add the following script in the TF file (such as main.tf):

```hcl
# Wait for the custom event channel and source to be ready
resource "time_sleep" "test" {
  create_duration = "3s"

  depends_on = [
    huaweicloud_eg_custom_event_channel.test
  ]
}
```

**Parameter Description**:
- **create_duration**: The creation delay time, set to 3s here to ensure the custom event channel and source are ready before creating the event subscription
- **depends_on**: Explicitly depends on the custom event channel resource

### 6. Create an Event Subscription

Add the following script in the TF file (such as main.tf):

```hcl
# Create an event subscription in the specified region (if the region parameter is omitted, it inherits the region specified in the current provider block)
variable "subscription_name" {
  description = "The name of the event subscription"
  type        = string
}

variable "sources_provider_type" {
  description = "The provider type of the event source"
  type        = string
  default     = "CUSTOM"
}

variable "source_op" {
  description = "The operation of the source"
  type        = string
  default     = "StringIn"
}

variable "targets_name" {
  description = "The name of the event target"
  type        = string
  default     = "HTTPS"
}

variable "targets_provider_type" {
  description = "The type of the event target"
  type        = string
  default     = "CUSTOM"
}

variable "transform" {
  description = "The transform configuration of the event target, in JSON format"
  type        = map(string)
  default     = {
    "type" : "ORIGINAL",
  }
}

variable "detail_name" {
  description = "The name(key) of the target detail configuration"
  type        = string
  default     = "detail"
}

variable "target_url" {
  description = "The target url of the event target"
  type        = string
}

resource "huaweicloud_eg_event_subscription" "test" {
  channel_id = huaweicloud_eg_custom_event_channel.test.id
  name       = var.subscription_name

  sources {
    name          = huaweicloud_eg_custom_event_channel.test.name
    provider_type = var.sources_provider_type

    filter_rule = jsonencode({
      "source" : [
        {
          "op" : var.source_op,
          "values" : [huaweicloud_eg_custom_event_channel.test.name]
        }
      ]
    })
  }

  targets {
    name          = var.targets_name
    provider_type = var.targets_provider_type
    connection_id = try(data.huaweicloud_eg_connections.test.connections[0].id, "")
    transform     = jsonencode(var.transform)
    detail_name   = var.detail_name
    detail        = jsonencode({
      "url" : var.target_url
    })
  }

  lifecycle {
    ignore_changes = [
      sources, targets
    ]
  }

  depends_on = [
    time_sleep.test
  ]
}
```

**Parameter Description**:
- **channel_id**: The ID of the event channel to which the event subscription belongs, assigned by referencing the ID of the custom event channel
- **name**: The name of the event subscription, assigned by referencing the input variable subscription_name
- **sources.name**: The name of the event source, assigned by referencing the name of the custom event channel
- **sources.provider_type**: The provider type of the event source, assigned by referencing the input variable sources_provider_type, defaulting to CUSTOM
- **sources.filter_rule**: The filter rule of the event source, defined in JSON format, where op is assigned by referencing the input variable source_op (defaulting to StringIn) and values references the name of the custom event channel
- **targets.name**: The name of the event target, assigned by referencing the input variable targets_name, defaulting to HTTPS
- **targets.provider_type**: The provider type of the event target, assigned by referencing the input variable targets_provider_type, defaulting to CUSTOM
- **targets.connection_id**: The connection ID of the event target, assigned by referencing the queried EG connection ID
- **targets.transform**: The transform configuration of the event target, defined in JSON format, assigned by referencing the input variable transform, defaulting to {"type":"ORIGINAL"}
- **targets.detail_name**: The key name of the target detail configuration, assigned by referencing the input variable detail_name, defaulting to detail
- **targets.detail**: The target detail configuration, defined in JSON format, where url is assigned by referencing the input variable target_url
- **lifecycle.ignore_changes**: Ignores changes to sources and targets to avoid differences caused by server-side default values
- **depends_on**: Explicitly depends on the time sleep resource to ensure the custom event channel and source are ready before creating the event subscription

### 7. Preset Input Parameters Required for Resource Deployment (Optional)

In this practice, some resources and data sources use input variables to assign configuration content, and these input parameters need to be manually entered during subsequent deployment.
At the same time, Terraform provides a method to preset these configurations through `tfvars` files, which can avoid repeated input during each execution.

Create a `terraform.tfvars` file in the working directory, with the following example content:

```hcl
# Authentication variables
region_name = "cn-north-4"
access_key  = "your_access_key"
secret_key  = "your_secret_key"

# Resource variables
channel_name      = "tf_test_channel"
source_name       = "tf-test-source"
subscription_name = "tf-test-subscription"
target_url        = "https://test.com/example"
```

**Usage**:

1. Save the above content as a `terraform.tfvars` file in the working directory (this file name allows users to automatically import the content of this `tfvars` file when executing terraform commands; for other names, `.auto` needs to be added before tfvars, such as `variables.auto.tfvars`)
2. Modify parameter values as needed
3. When executing `terraform plan` or `terraform apply`, Terraform will automatically read the variable values from this file

In addition to using the `terraform.tfvars` file, you can also set variable values in the following ways:

1. Command line parameters: `terraform apply -var="channel_name=my-channel"`
2. Environment variables: `export TF_VAR_channel_name=my-channel`
3. Custom named variable files: `terraform apply -var-file="custom.tfvars"`

> Note: If the same variable is set through multiple methods, Terraform will use variable values according to the following priority: command line parameters > variable files > environment variables > default values.

### 8. Initialize and Apply Terraform Configuration

After completing the above script configuration, execute the following steps to create resources:

1. Run `terraform init` to initialize the environment
2. Run `terraform plan` to view the resource creation plan
3. After confirming that the resource plan is correct, run `terraform apply` to start creating the custom event subscription
4. Run `terraform show` to view the created custom event subscription
